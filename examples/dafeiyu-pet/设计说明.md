# 鲸鱼女仆桌宠：动作 Sprites 设计说明

## 1. 设计目标

打造一只会陪伴、会回应、偶尔自己找乐子的鲸鱼主题女仆桌宠。它应在不打扰用户工作的前提下，让用户通过少量直觉操作感受到鲜明个性。

- **完整可用**：具备站立、移动、休息、拖拽、跌落、落地等基本状态和必要过渡。
- **反应丰富**：不同触碰部位、操作节奏、停留时长、边界及桌面事件产生不同反馈。
- **角色鲜明**：以长发、呆毛、鲸鱼尾巴、海洋元素和女仆礼仪构建动作辨识度。
- **适合量产**：按基础动作、过渡、表情及特效拆分；优先共用姿态，不为每个情境重复绘制完整动画。
- **不喧宾夺主**：默认安静、可打断；特效、声音及提醒可关闭，避免遮挡和持续诱导交互。

### 角色气质

建议塑造为「认真尽职但有点冒失的海洋小女仆」：迎接时有礼貌，好奇时身体前倾，被夸奖会害羞，受到惊吓时尾巴先一步暴露情绪。她有自己的小习惯，但不设饥饿惩罚、负面好感度或强制照料。

### 不做什么

不改变参考图的核心服装和身体结构；不假设已经有某个桌宠引擎、系统权限或资源管线；不以读取用户私人内容作为触发条件。文中的物理、窗口交互和桌面事件均为待实现的设计能力。

## 2. 角色造型与动画约束

### 2.1 必须保留的识别点

1. **轮廓**：Q 版大头小身，深蓝至浅蓝渐变长发，头顶单根弧形呆毛。
2. **面部**：大蓝眼、柔和红晕，表情变化清晰，但不要改变五官位置与脸型。
3. **头部装饰**：白色女仆发箍、两侧蓝色蝴蝶结与深蓝鳍状装饰。
4. **服装**：深蓝女仆裙、白色褶边与围裙、领口蓝色宝石，围裙正面保留小鲸鱼标记；袖口、裙边的细小金色装饰可在小尺寸适当简化。
5. **尾巴**：深蓝鲸鱼尾巴，从背后伸出，尾鳍完整可辨；与头发、裙摆区分层次，不画成鱼腿或替换双脚。
6. **脚部**：白色袜口、深色圆头鞋及小蝴蝶结；站立、行走时双脚始终是地面接触主体。

参考图展示了正面、侧面和背面；动作默认以正面及侧面为主，背面用于特定动作。未明确展示的结构以参考图能确认的形态为准，避免擅自增加设定。

### 2.2 动作语言

- **运动主次**：头身先动，长发和裙摆稍滞后，尾巴在受力后再回摆；呆毛用于加强情绪。
- **力度节制**：闲置动作轻、交互反应清晰，惊吓可短暂夸张但迅速回稳。
- **稳定尺度**：同一角色不同动作保持统一头身比例、主体大小和地面高度；禁止帧间忽大忽小、左右漂移。
- **透视一致**：正面与侧面分别建立参考姿态；转身应经过中间姿态，不把正面直接变成侧面。
- **遮挡明确**：发丝、手臂、围裙、尾巴前后关系随姿态合理变化，尾巴不穿过身体。
- **小尺寸优先**：先保证眼睛、手势、尾鳍和动作轮廓可读，再添加小饰品与粒子。

## 3. 素材与播放约定

以下为建议规格，不绑定引擎：

| 项目 | 建议 |
|---|---|
| 交付格式 | 每帧透明背景 PNG；另可按动作输出等尺寸 Sprite Sheet，保留原始逐帧文件 |
| 工作画布 | 建议统一 512×512 px；最终显示可缩小，先做目标尺寸可读性验证。较大动作可采用单独画布，但须保留一致的角色尺度与锚点元数据 |
| 基准与锚点 | 地面动作以双脚接地点中心作为逻辑锚点；空中动作以身体稳定点为锚点，并提供落地点偏移。锚点用画布像素或归一化坐标明确记录 |
| 锚点示例 | 若地面基准采用 512×512，可暂定脚底锚点 `(256, 460)`；预留尾鳍、头饰和特效空间，最终数值由基准帧确定 |
| 裁切与留白 | 同一动画各帧统一画布、尺寸、锚点；不对每帧独立自动裁切后直接播放。确认长发、尾鳍及头饰不会出框 |
| 帧率 | 普通动作建议 8–12 fps，强调反应可达 12–15 fps；特殊停顿用逐帧时长表达 |
| 命名 | `类别_动作_方向_序号.png`，如 `move_walk_right_000.png`；另记录循环方式、fps、锚点和可中断点 |
| 循环 | 循环帧首尾衔接；单次动作用进入、停留、退出明确收束；不把重复首尾帧误算为不同姿态 |
| 左右朝向 | 先制作右向；只有确认蝴蝶结、围裙图案和所有不对称细节可接受镜像后才复用左向，否则单独绘制或局部修正 |
| 图层 | 角色主体、手持物、泡泡等特效优先分层，避免特效遮脸；运行环境不支持时可烘焙，但应保留源层 |

**资源包建议**：每个动作交付逐帧图、动画预览、动作清单；清单包含动作 ID、方向、帧数、每帧时长或 fps、循环方式、锚点、建议触发、过渡/中断规则。特效若独立交付，同样记录坐标、层级及同步时点。帧数是独立绘制帧的预估，不包含运行时延时复用；最终数量以实际验收为准。

## 4. 基础动作库

优先级：**P0** = 桌宠完整运行的基础；**P1** = 形成角色个性与常用互动；**P2** = 扩展表现。帧数为每个方向或阶段的建议范围，不是总计。

| ID | 动作 | 画面与关键帧 | 帧数 / 播放 | 优先级 |
|---|---|---|---|---|
| `idle` | 站立待机 | 双脚稳定；轻微呼吸，头发和尾尖缓慢摆动 | 6–8，循环 | P0 |
| `idle_blink` | 眨眼 | 睁眼→半闭→闭眼→睁眼；保持站姿 | 3–4，单次，可叠加 | P0 |
| `turn` | 转身 | 眼神先行→身体旋转→发尾和尾鳍跟随回稳 | 4–6，单次 | P0 |
| `walk_start` | 起步 | 重心前移，一脚抬起，尾巴反向平衡 | 3–4，单次 | P0 |
| `walk` | 行走 | 双脚交替、身体微起伏，裙摆与尾巴错峰摆动 | 6–8，循环 | P0 |
| `walk_stop` | 停步 | 收脚→重心回正→发尾、尾巴回稳 | 3–4，单次 | P0 |
| `run` | 小跑 | 步幅比行走大，身体前倾，尾巴跟随摆动 | 6–8，循环 | P1 |
| `sit_down` / `sit_idle` / `stand_up` | 坐下、坐姿、起身 | 扶裙坐下，尾巴自然铺到一侧；起身后回稳 | 4–6 / 4–6 / 4–6；中间循环 | P0 |
| `sleep_enter` / `sleep_loop` / `wake` | 困倦入睡、睡眠、苏醒 | 点头→闭眼；睡眠轻呼吸；醒来揉眼伸展 | 5–8 / 4–6 / 5–8；中间循环 | P1 |
| `drag_pickup` / `drag_hold` | 拎起、拖拽悬空 | 被抓取时惊一下；悬空时脚离地、裙发和尾巴下垂，避免展示不适当姿态 | 3–5 / 4–6；后者循环 | P0 |
| `fall` | 下落 | 手脚轻张、长发上扬，表情吃惊；与拖拽悬空区分 | 4–6，循环或保持 | P0 |
| `land_soft` / `land_heavy` | 轻落地、重落地 | 接地→身体下压→尾巴回摆→站稳；重落地更明显但不受伤 | 各 4–6，单次 | P0 / P1 |
| `edge_stop` | 屏幕边缘刹停 | 脚步缩短、探身→停住→往回看 | 4–6，单次 | P0 |
| `appear` / `goodbye` | 登场、退场 | 登场整理围裙后行礼；退场挥手，可接轻微泡泡淡出 | 各 5–8，单次 | P1 |

**简化路径**：若首版不支持自由下落或睡眠，保留对应素材规划，但不要把无法触发的状态标成已实现。动作完成时，优先回到与该动作姿态兼容的待机或过渡，不强行瞬切站姿。

## 6. 用户互动与反应

### 6.1 指针与触碰

碰撞区域按头部、脸部、身体、尾巴划分；可见的头发不必全部算作头部，避免误触。下列触发使用桌宠窗口内的输入事件，不要求全局监听。

| ID | 触发 | 表现与反馈 | 帧数 | 优先级 |
|---|---|---|---|---|
| `hover_curious` | 指针停留角色附近片刻 | 视线跟随、歪头；离开后回正 | 4–6 | P1 |
| `pet_head` | 缓慢摸头 | 闭眼微笑，身子轻贴手势，尾鳍轻摇 | 6–8，短循环 | P0 |
| `pet_head_happy` | 连续温柔摸头 | 脸红、双手贴胸，尾巴开心拍动；小爱心可选 | 6–8 | P1 |
| `poke_head` | 单击头部 | 眨眼抬头，呆毛弹一下 | 4–6 | P0 |
| `poke_cheek` | 单击脸颊 | 脸颊轻鼓，歪头看向指针 | 4–6 | P1 |
| `poke_body` | 单击身体 | 轻退半步，整理围裙后微笑 | 5–7 | P0 |
| `poke_tail` | 单击尾鳍 | 尾巴先缩一下，再转身看自己的尾巴 | 5–8 | P1 |
| `poke_repeat` | 短时间连续点击 | 小幅鼓脸、双手护住身体；停止后很快恢复 | 6–8 | P1 |
| `cursor_play` | 用户在角色附近缓慢移动指针 | 目光追随；偶尔伸手碰虚拟泡泡，不强制追踪 | 6–8 | P2 |
| `drag_react` | 按住后移动超过拖拽阈值 | 由惊讶转悬空；释放后根据位置进入落地或下落 | 见基础动作 | P0 |

**输入判定建议**：按下后移动超过系统拖拽阈值才进入拖拽，未超过则按点击处理；长按可进入轻抚，需避免松手时再触发点击。摸头可使用头部区域内连续缓慢往返或长按作为条件；这些阈值由实际交互测试调优。频繁点击的反馈偏幽默，不惩罚用户，也不持续锁住角色。

## 7. 情绪表现与复用

情绪是动画演出，不是需要数值维护的养成属性。可先做表情覆盖层及少量专属姿态，减少重复绘制：

| 情绪 | 眼睛 / 嘴 | 身体 / 尾巴 | 典型动作 |
|---|---|---|---|
| 平静 | 自然睁眼、浅笑 | 尾尖缓摆 | 待机、坐姿 |
| 开心 | 弯眼、笑嘴、轻红晕 | 挺身、尾鳍快速轻摆 | 摸头、击掌 |
| 好奇 | 睁大眼、微张嘴 | 歪头、身体前倾 | 指针停留、边缘探头 |
| 害羞 | 眼神躲闪、脸红 | 双手贴胸，尾巴部分遮身 | 被夸奖、收礼 |
| 惊讶 | 睁大眼、小圆嘴 | 呆毛上扬，尾鳍绷紧 | 被拖拽、落地 |
| 小别扭 | 鼓脸、视线偏开 | 双手抱胸，尾巴轻甩一次 | 反复点击 |
| 困倦 | 半睁眼、打哈欠 | 点头、尾巴缓慢垂下 | 休息、睡眠 |

复用前提：表情层与对应头部运动、朝向、遮挡匹配；不匹配时绘制专属帧。情绪结束应有回归过渡，不将鼓脸、惊讶等表情永久残留。

## 8. 状态、优先级与打断

### 8.1 状态流

```text
登场 → 站立待机 ↔ 行走 / 小跑
          ↕             ↓
      坐下 → 坐姿 → 起身 ← 边界刹停 / 转身
          ↓
      入睡 → 睡眠 → 苏醒

任意可交互状态 → 拎起 → 拖拽悬空 → 释放
                                      ├→ 有支撑：落地 → 待机
                                      └→ 无支撑：下落 → 落地 → 待机
待机 / 坐姿 → 短反应或自主动作 → 对应的待机 / 坐姿
```

图中「任意可交互状态」不包含退场或引擎已卸载等不可交互阶段。没有空中物理时，释放应由运行时确定一个安全落点，再接落地表现；不要空放 `fall` 循环。

### 8.2 优先级与恢复

从高到低建议为：**退出与资源卸载 > 拖拽及安全位置修正 > 支撑变化/落地 > 用户主动交互 > 用户发起的计时或功能事件 > 自主动作 > 普通待机**。

- 拖拽可以打断行走、睡眠和大部分表演；记录被打断动作的基础姿态，结束后回到安全待机，不强求从中断帧续播。
- 空中时，摸头等普通反应不打断安全相关动作；可忽略或仅保留最近一次请求，落地后再确认是否仍有效，不无限排队。
- 睡眠被触碰时先进入苏醒过渡，再处理仍有效的交互；拖拽立即生效，不等待苏醒。
- 用户取消、窗口消失、角色被拖走时，中止击掌、泡泡等等待交互，清理道具和命中区域。
- 单次表演有明确结束或超时；循环动作必须有可退出条件。相同短反应在短时间内合并，避免连点产生长队列。
- 表情和特效可叠加的前提是不会破坏当前姿态、遮挡表情或挡住用户操作。

## 9. 互动节奏与用户控制

以下是起始建议，实际体验应允许调节：

- 自主短动作：20–45 秒一次，带随机间隔和最近动作去重；长动作至少间隔 2 分钟。
- 同一触碰反应：约 0.5–1 秒冷却；短时间多次点击转入 `poke_repeat`，停止后恢复。
- 指针跟随：停留约 0.5 秒再响应，视线转动有回中缓冲，不让眼球高速抖动。
- 击掌、泡泡等邀请：等待约 5–8 秒后自然结束；未响应不连续重试。
- 默认关闭声音；音效独立开关与音量，特效、主动邀请、自主走动、置顶/穿透等应由实际产品能力决定是否提供设置。
- 屏幕遮挡优先级低于用户操作；提供暂停互动或安静模式。系统级功能必须由用户明确开启并遵循平台权限。

## 10. 动作制作拆解示例

### A. 摸头 `pet_head`

1. **预备**：指针进入头部区域并满足轻抚判定，眼神上移，呆毛轻压。
2. **主动作**：身体向触碰方向小幅倾斜，半闭眼→闭眼微笑，双手自然贴胸。
3. **次级运动**：头发稍滞后，尾鳍以较小幅度左右摇；不让发箍或蝴蝶结滑位。
4. **持续**：维持 6–8 帧短循环，间隔可插入轻微表情变化；不要强行累计时长。
5. **退出**：松开或离开命中区后，睁眼、头部回正、尾巴回稳，回到原本安全的待机姿态。

### B. 尾巴被点 `poke_tail`

1. 尾鳍被点时先小幅收缩，身体稍后才反应。
2. 角色转头看向尾巴，眼睛睁大；尾巴绕开裙摆，不穿模。
3. 发现是用户后表情转为疑惑或微笑，尾巴回到自然摆放。
4. 结束回待机；若此时发生拖拽，直接切入抓取状态并清理反应。

### C. 拖拽与释放

1. 确认超过拖拽阈值后，短暂惊讶并离地；脚不再贴地。
2. 悬空持续时，角色主体相对于抓取点稳定；头发、裙摆、尾巴有有限惯性，不遮住面部。
3. 松开后根据实际支撑与平台能力，选择轻落地、重落地或下落。
4. 接地帧脚底与地面锚点对齐；身体缓冲后稳定，避免反复弹跳。

## 11. 分期与交付清单

### 第一批：可用核心 P0

站立和眨眼、转身、行走起停、坐下与起身、拎起与拖拽、下落与落地、边缘刹停、摸头、头部/身体点击。先验证一个朝向和目标显示尺寸，再扩展方向。下落依赖运行时支持；如暂不支持，应注明并延后对应素材验收。

### 第二批：个性与常用互动 P1

登场退场、小跑、睡眠、观察、整理围裙和头发、尾巴摆动、吹泡泡、脸颊和尾巴点击、重复点击、击掌与泡泡互动。优先复用第一批的身体、表情和过渡。

### 第三批：情境扩展 P2

跳舞、躲猫猫、礼物、一起休息、更多自主生活动作、窗口互动、计时与时间问候。先确认产品侧存在相应能力或入口，再投入素材制作。

### 每批交付

- 对应动作的透明 PNG 序列、必要的图集、源工程或保留图层的源文件。
- 按动作组织的预览和元数据清单：ID、方向、帧数、逐帧时长或 fps、循环方式、锚点、触发与退出、可打断点。
- 角色基准帧和颜色、轮廓、装饰位置对照；特效与道具单独列明。
- 左右镜像是否可用、非对称元素处理、运行时依赖与未制作项。

## 12. 验收标准

1. **人设一致**：发色渐变、呆毛、发箍、鳍状装饰、围裙鲸鱼图案、尾巴与鞋袜可识别，无服装结构突变。
2. **尺度稳定**：同朝向的头身比例和主体尺度一致；站立、行走、落地之间脚底锚点稳定，无不应有的漂移或缩放。
3. **动画连续**：逐帧检查和实际速度播放均无跳帧、穿模、断裂、尾鳍裁切或首尾突兀；转身及状态切换有自然过渡。
4. **交互可理解**：点击、轻抚、拖拽可区分；命中反馈及时；重复输入、取消、拖拽打断后不会卡住、漏清道具或长时间排队。
5. **位置安全**：落地贴合支撑面，拖拽释放后不会不可恢复地消失在屏幕外；不支持的窗口或物理功能不误触发。
6. **显示可读**：在实际目标显示尺寸、浅色和深色背景下检查面部、手势、尾鳍及透明边缘；不以放大后的素材观感代替实际表现。
7. **舒适可控**：自主行为、音效、特效及提醒的频率和开关符合产品实现；没有持续遮挡、闪烁、无休止邀请或强制养成压力。
8. **交付可接入**：动作 ID 与文件一一对应，方向、帧数、播放时长、循环、锚点和前置能力完整，缺失项显式标注。
