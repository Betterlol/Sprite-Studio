# 统一区域配置与可操作切割工作台

## Context

用户明确要求：参考旧版已经可用的切割操作闭环，保留新版性能、稳定身份和安全发布优势；网格/透明连通域是生成切割区域的快捷操作，方法属于工具参数，不再是配置中的运行模式。最终配置只保存一组可自由编辑的区域。Agent 与人使用同一份配置。禁止 subagent 实现，只允许用于 review。

当前隔离分支 `worktree-slice-preview-ux` 基于最新 main `86f7366`，源码干净。已有旧版实现已核对：主画布选中/移动/八方向缩放/新增区域，底部原帧缩略图与选区联动，右侧只编辑所选区域，高级参数折叠。此次恢复该闭环，不另造配置控制台，不修改模型、任务流程或正式素材。

## 需求与最终设计

### 统一保存对象
- 新配方 v3 保留 sheet-recipe 与 `slicing.items`，条目统一为稳定 `id? / name / enabled / box`，必要时含不可变像素选区引用。配置没有 `method/grid/detection/componentKeys`，生成参数仅作为工具调用入参和网页本地偏好。
- 保留输出目录、明确的统一输出画布/比例/放置能力，但放在高级输出设置；生成区域时给出合理画布建议，默认不逐帧缩放。原帧预览与正式输出预览区分，切割不强迫人操作所有处理字段。
- v1/v2 仍按旧规则读取/执行，不自动迁移或重写工程。进入新编辑器时通过只读解析将旧配方转成 v3 草案，保留现有 ID、实际源框及旧输出设置；明确保存才写新格式。
- 连通域的像素归属固化为有源内容哈希、原始框和图片哈希校验的不可变选区对象，不将阈值/算法/组件 key 隐藏在新配方中。执行 v3 不再跑连通域。未改动的区域保留掩码避免串帧；改动框的几何范围后该区域转为普通矩形取像，删除旧掩码绑定，预览如实反映。
- 区域 ID 与顺序分离，移动/缩放/重排/改名不换身份；新区域省略 ID，保存由后端分配。不按检测序号继承 ID。已有引用、CAS、幂等、原子发布、源和输出基线及最终发布屏障继续有效。

### 生成是操作，不是配置
- 扩展现有 `inspect_sheet`，提供只读区域生成：grid 接收行列/边距/间距，components 接收透明度/最小像素等参数，返回相同的区域草案和实际证据；不保存配方、不创建正式切片。
- 增加只读旧配方解析入口，使人和 Agent 都能显式取得统一可编辑草案；保留旧 detect/preview 调用兼容性。输出提供按批原帧/输出帧的实际 PNG，供底部缩略图和选中帧预览使用，不仅返回拼图。
- Agent 路径为：生成区域（可选）→ 读取/修改统一区域配置 → 预览 → write_documents → slice_sheet；微调不需再次指定生成方法，不触发识别/生图。不增加每帧人工审批。
- 新操作复用现有读取/检查父权限、任务源范围、队列取消与真实图片证据；掩码引用不能访问任意路径、伪造来源或悄悄覆盖文件。

### 网页恢复旧版操作闭环
- 主画布始终是切割工作区：原图与区域叠加，选区可移动、八方向缩放，空白处框选新增；Delete 删除、方向键微移、Escape 取消拖动；编辑控件聚焦时不拦截其按键。允许区域重叠，坐标为原图像素，拖拽自动限制在图像范围内。
- 底部显示原帧缩略图，点击联动画布与右侧属性；原帧与统一输出效果可切换查看，选中帧、尺寸、帧数、加载/过期/溢出状态明确。
- 右侧默认仅显示所选区域的名称、位置/尺寸、启用、删除等常用操作。识别阈值、边距间距、输出目录/画布/缩放、JSON 和诊断放入默认收起的高级区，不展开整组坐标表、UUID 或组件 key。
- 网格/连通域生成控件是工具栏操作。网格参数调整在未进入手动编辑前更新草案；首次成功移动/缩放/新增/删除等区域编辑后显示“手动调整”，生成规则不再控制区域。选择、视图缩放、取消拖动不改变模式。重新生成替换手工草案前明确确认，不悄悄覆盖；仅完全相同区域可安全复用已有 ID。
- 提供撤销/重做。常用“保存当前切割”串起保存配置和执行，但如执行失败必须区分“配置已保存、切片未更新”，保留可恢复草案；高级入口仍可只保存配置。

### 性能和冲突
- 指针移动只在前端以 requestAnimationFrame 更新临时几何，不请求 Python、不保存、不跑连通域；pointerup 一次提交编辑，取消恢复旧框和模式。
- 原图解码/选区对象/实际缩略图复用缓存；结束拖动或短暂空闲后按可见批次更新预览，不逐帧重复跑整组识别；选择帧/缩放视图不重算切割。
- 保留 128 帧、16 帧预览批次、源图/输出解码/连通扫描限额；预览与草稿版本绑定，晚回复/跨工程/ABA/409 不覆盖新输入，过期结果有明确标识。

## 实施顺序与复用

1. 保存需求设计到本工作树文档，准备独立依赖及 protocol，运行基线；不提交/推送、不修改其他工作树和运行中的正式服务。
2. 亲自扩展 `studio/sheet-schema.ts`、`studio/sheet_imaging.py`、`studio/sheet-inspection.ts`、`studio/sheets.ts`：v3 统一区域、固化选区、生成/旧配方解析、按帧预览与兼容。复用 `ImagingWorker`、`checkedPng`、`imagePath`、`publishFiles`，不新增依赖或图像处理管线。
3. 亲自接入 `studio/agent.ts`、`studio/mcp.ts` 和既有检查路由/权限，更新真实使用指令，验证实际工具分发的生成→改配置→切割→动画检查链路（不调用模型）。
4. 亲自实现集中的切割工作台组件与小型纯状态/几何模块，接入 `web/App.tsx` 的中央区域和属性 portal，替代原来堆叠式 `SliceConfigPanel`；沿用现有布局、图标、缩放及 CSS token，不重设计全站。
5. 程序回归与隔离真实浏览器验证后，只派一个只读 review subagent 检查完整差异；修正具体问题并定向复验。
