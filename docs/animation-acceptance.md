# 动画候选播放验收

## 目标与职责

保存生成图集只代表素材入库，不能代表用户接受动画效果。助手完成切割、编排及必要调整后，提交可播放的候选版本；用户在工具审批中接受或拒绝该候选。

助手继续负责制作和检查，用户决定视觉效果是否接受。位置、尺度、帧差异等检查材料不是质量合格门槛，不新增视觉评分、硬阈值、自动重生成或返工次数状态机。

## 方案取舍

- 仅调整提示词或增加静态叠图不能提供可靠的播放验收，也不能覆盖直接写动画配置。
- 新增独立验收工具会把保存和验收拆成可遗漏的两次调用。
- 采用现有工具权限与保存调用：在 ask 时附上固定快照播放，决定回到同一次调用。沿用 allow / ask / deny；不恢复旧任务层。

## 工具与发布路径

- save_clip_draft：使用现有完整草稿预览生成修改前、候选快照。普通草稿接受后保存；人工草稿派生结果仍只交付待采用，不直接覆盖人工正文。
- save_frame_draft：沿用现有帧草稿版本保护和保存能力，使用同样的播放验收界面。
- write_documents：切割配方和草稿正文照常保存。直接写正式动画时，也进入同一成果审批，继承动画保存权限；批量写入仍整体接受/拒绝、原子提交，不能借换工具跳过动画审批。
- 默认图片入库、完整动画保存和帧调整保存为 ask。已有显式 allow / deny 设置不偷偷改写；旧配置如使用直接执行，可在工具权限界面一键启用动画播放验收。
- allow 只是免确认执行，不能称为用户已验收。deny 不执行。ask 的 Accept / Deny 及文字意见返回实际工具结果；Deny 保留草稿，不自动生成，不自动回滚其他已完成素材。

## 审批与版本

审批展示完整候选，不以 inspect_clip 的最多16帧静态检查范围截断。每项包含修改前/候选固定快照、帧数、总长、循环、变更摘要和已有边界警告。

候选绑定草稿正文版本、正式动画基线和图片内容。接受时及实际提交前复查，变化则拒绝保存旧候选并提示重新提交。预览快照来自真实渲染，不以 Agent 的质量结论代替用户决定。

审批只是当前调用的决定，不新增长期任务/验收锁。停止、服务关闭和重启沿用现有取消/恢复行为；取消不伪装成用户视觉拒绝。

## 界面

动画成果请求自动打开模态框，可暂时收起后从审批卡重新打开，不会因关闭弹窗而默认接受或拒绝。复用固定快照及帧渲染地址。

- 候选按真实帧时长播放，默认原速；已有动画可同时对比修改前版本。
- 暂停、从头播放、逐帧、统一缩放及棋盘格/浅色/深色背景。
- 空动画显示无帧，不访问不存在的帧。候选与原版共用视图比例，不逐帧自动放大。
- 显示反馈输入框，Accept（接受并保存，或交付待采用）/ Deny（不应用并返回意见）。图片或快照加载失败时显示错误，不静默显示空画面。
- 多动画批量写入在同一请求中逐项查看，一次决定整批。

## 开发者测试入口

旧版本已经保存过工具权限时，原来的显式 allow 会保留。在“助手工具权限”中点击“启用动画播放验收”，将完整动画保存与帧调整保存设为 ask，即可启用新交互；不需要开启旧任务系统。

建议由开发者覆盖：首次编排动画、修改已有动画、帧调整、接受附带意见、拒绝附带意见、收起后重开、空动画、多动画批量写入、审批期间修改版本以及人工草稿交付待采用。

## 本轮边界与检查

不新增智能去底、局部重绘、分层动画、视觉评分或质量阈值。这些能力不作为本次验收弹窗的前置条件。

按用户要求，不运行网页、测试套件、构建、类型检查或模型验证。补充回归用例但不运行；交付时列出实际静态检查范围，由开发者测试。
